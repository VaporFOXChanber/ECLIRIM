# Internationalization maintenance

`src/shared/messages.json` is the single source of truth. Every entry has a stable `id`, the original Japanese `ja` source, and an English `en` translation. IDs were initially generated from the Japanese source; retain an existing ID when editing its wording. The catalog is data, never executable HTML from an external source.

UI code calls `t(source, substitutions)` or `t(id, substitutions)`. Numbered `{0}` placeholders are replaced by a callback, so user content containing `$&`, braces, or markup stays literal. Use textContent or DOM nodes for all user data. The popup’s start-button HTML contains only trusted static catalog content.

Static HTML uses `data-i18n`, `data-i18n-title`, `data-i18n-placeholder`, `data-i18n-aria-label`, and `data-i18n-label`. Text is assigned directly, without translating control IDs, values, preset names, user text, or page content. Inline text spans preserve emphasis and controls. English adds a space at adjacent inline word/sentence boundaries without inserting one before punctuation. Pages stay hidden until their saved language is read and their static UI is localized.

Build runs `scripts/locales.mjs`, rejecting duplicate IDs/sources, missing translations, and differing placeholders. It writes `dist/_locales/{ja,en}/messages.json`; do not edit generated files. `default_locale` is English. Native Chrome descriptions use named catalog aliases. `chrome.i18n.getUILanguage()` resolves Automatic; `getMessage()` supplies native messages when the chosen language matches Chrome. Manual overrides and missing/empty native messages use the bundled catalog, falling back to English then the source.

`chrome.storage.local.language` is independent of settings, profiles, presets, comparison state, and backup schema. Invalid/missing values mean Auto. The listener is installed before the initial read; a revision counter prevents a late read from overwriting a newer choice. No default is written on read failure. Saving changes only `language`.

Language changes reload extension UI documents after queued setting writes finish. They do not reload the extension, video tab, or renderer. Open comparison state remains in storage. Saved feedback drafts remain, but the Wizard preview restarts and diagnostic review consent resets on any UI reload. Manifest descriptions remain controlled by Chrome UI language.

Status identifiers and Japanese legacy status details remain unchanged on the internal message wire. `localizeText` translates those known messages only at the UI boundary; parameterized status messages have anchored catalog-derived patterns. Do not run it over user presets, feedback input, tab titles, or page content. Machine-readable diagnostic attachments preserve their enum identifiers.

`feedbackText` and `diagnosticsText` take an optional localized flag. The default keeps canonical text compatible with existing tests/receiver behavior; UI preview/copy uses the localized mode. Delivery still sends the same structured fields, and canonical text still drives retry identity. No language or browsing metadata is added to the payload.

Test setup and required baseline archives: [Developer guide](DEVELOPMENT.md).

Tests:

```sh
npm run check
npm run test:i18n
npm run test:e2e
```

On macOS, `--lang` alone does not change Chrome UI language. The browser suite launches disposable visible Chrome for Testing processes with a process-only `AppleLanguages` argument. It does not write macOS defaults or touch existing Chrome profiles. English, Japanese, and French native locale reads are checked explicitly, together with manual override, same-folder 0.9.8 update, browser restart, all settings tabs, and 320px popup layout.
